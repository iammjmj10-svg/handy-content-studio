# 숏폼 기획 파이프라인

숏폼(릴스) 제작 프로세스의 기획 단계 3개를 순서대로 자동 진행한다:
**① 레퍼런스 골격 선정 → ② 장면별 기획안 → ③ 촬영가이드라인**

## 입력 파싱

인자에서 다음을 파악한다. 없으면 사용자에게 물어본다:
- **고객사/브랜드명** (필수)
- **제품·주제 정보** (필수 — 어떤 제품/서비스의 어떤 메시지인지)
- **레퍼런스** (선택 — 새 릴스 URL, 영상 파일, 대본 텍스트 중 하나)

## 0단계: 고객사 컨텍스트 로드 (반드시 먼저)

두 곳을 모두 읽는다:

**(A) 팀 공용 가드레일 — repo `guardrails/[고객사].md`** (있으면 최우선)
- 팀원 누구나 공유하는 고객사별 제품 사실관계·표현 금지선·프로모션·운영 규칙.
- 예: `guardrails/나아봄.md` (제품·화장품 표현금지·대표 확정 가이드·프로모션·메타광고 로직 포함)

**(B) 개인 메모리** `/Users/shinminjeong/.claude/projects/-Users-shinminjeong-Desktop-development-cardnews/memory/`
- `project_*` — 고객사 정보, 타겟, 진행 현황
- `reference_*` — 해당 고객사용 벤치마킹 릴스 골격
- `feedback_*` — 표현 금지선·가드레일 (예: 화장품 표현금지, 보장·효과 단정 금지, 숫자·% 금지 등)

**가드레일은 기획안 전체에 무조건 적용한다.** 고객사 파일이 없으면 신규 고객사이므로 제품 사실관계·타겟·표현 금지선을 사용자에게 확인하고, 확인된 내용은 작업 후 **`guardrails/[고객사].md`(팀 공용) + 메모리**에 저장한다.

## 1단계: 레퍼런스 골격 선정 (노션 "잘된 릴스 분석" DB에서 매칭)

레퍼런스 원천은 사용자가 직접 모아 분석해둔 노션 DB다. 여기서 클라이언트에 맞는 골격을 뽑는다:
- DB: `https://app.notion.com/p/3842d4d04f34800bbdf7d3c56a57ac32` (데이터소스: `collection://3842d4d0-4f34-806c-8161-000b3a78bc95`)
- notion-query-data-sources(SQL)로 전체 목록을 뽑은 뒤 **3축으로 매칭**한다:
  1. **업종 유형** (건기식/뷰티/식당/반려동물/IT/제품/플랫폼 등)
  2. **목적** (브랜딩 vs 전환율)
  3. **타겟** (연령대 + 타겟 니즈: 제품구매/가치입증/방문/높은 감도 등)
- 업종 정확 일치 > 목적 일치 > 니즈 일치 순으로 가중. 자사 검증 사례(자사/타사=자사)는 우선순위 ↑
- 상위 후보의 상세 페이지를 notion-fetch로 열어 **재활용 공식(흐름패턴)·후킹유형·신규발견요소**를 확인하고, 클라이언트 사실관계로 재현 불가능한 요소(예: 판매량 1위, 택배 물량 등 대세감 과시)는 제외하거나 부분 차용으로 강등한다.
- 새 레퍼런스 영상이 주어지면 분석 후 이 DB 포맷대로 노션에 추가하는 것을 제안한다.

**원칙: 복붙 금지, 골격만 차용.** 어떤 골격을 왜 골랐는지 후보 비교와 함께 사용자에게 보고한 뒤 2단계로 진행한다.

## 1.5단계: 대본·소구 작성 로직 (전 고객사 공통 — 골격을 고객사 버전으로 옮길 때 반드시 적용)

### ① 콜드 타겟 훅 — 제품명 먼저 ❌ → 상황·궁금증 먼저 ⭕
- 광고를 처음 보는 사람은 브랜드를 모른다. 훅을 제품명으로 시작하면 "그게 뭔데?" 하고 이탈한다.
  - ❌ "OO수딩스틱 정가로 사려던 분~" (아는 사람 전제)
  - ✅ "맘카페에서 완판됐던 그 아이 진정 스틱~" / "애 가려워하는 데 바를 거 찾으셨죠?" (상황·궁금증·사회증거)
- **브랜드명은 2~3번째 컷에서 공개한다.**

### ② 소구점 반복 방지 — 영상마다 히어로 강점 1~2개만
- 시리즈로 여러 편 만들 때 매 영상이 "성분→원리→효과→간편→CTA" 똑같은 블록이면 계정이 지루해지고 소재 피로도가 생긴다.
- 영상마다 **히어로 강점 1~2개만** 골라 밀고, 나머지 강점은 한 줄로만 넣거나 생략한다.
- 같은 팩트도 표현을 바꾼다(은유·대구·아이/사용자 시점·Q&A·리뷰 인용). 예: 안전성 → "진짜 발라도 돼요? Q&A" / 성분 → "덜어내고 → 채웠다 대구법".
- 화자도 나눈다: 공식계정=브랜드 화법("저희가 만들었어요") / 체험단·UGC=경험담 화법.

### ③ 광고 ↔ 상세페이지(랜딩) 핏
- 광고 소구와 랜딩 첫 화면이 어긋나면 클릭해도 전환 안 되고 이탈한다. (클릭률 좋은데 구매 0이면 대부분 이 문제)
- 랜딩(상페)의 핵심 키워드를 광고에도 다리로 남긴다. (예: 상페가 "모기" 중심이면 광고에서 모기를 완전히 빼지 말 것)

### ④ 전환/커머스 소재의 근거는 "실제 사실"만 (허위·과장 금지)
- 완판·재입고·품절·기간한정·가격할인·평점·후기는 **실제일 때만** 사용한다.
- ❌ 허수 정가로 부풀린 할인율("정가 12만→86% 할인"), 조작된 할인 명분("수출물량 확보" 등), 미확인 사은품·환불보증, 없는 판매량/대세감.
- 확실치 않은 수치·혜택·마감일은 반드시 클라이언트 확인 후 반영한다. (없으면 "확인 필요"로 비워둔다)

### ⑤ 톤은 브랜드 결 유지
- 레퍼런스가 하드셀(가격파괴 홈쇼핑·남성 고성 등)이어도 **프리미엄 브랜드에 그 톤을 그대로 쓰면 이미지가 훼손**된다.
- 긴박감은 희소성(완판·한정)으로 만들고, 말투는 브랜드 결(다정·신뢰 등)로 유지한다.

## 2단계: 장면별 기획안 (HTML 아티팩트)

`feedback-scene-plan-rules.md` 메모리의 규칙을 전부 적용한다. 핵심 요약:

- HTML 아티팩트, 2컬럼 테이블 (장면 | 자막), 전체 가운데 정렬
- 제목: `[브랜드명] 콘텐츠 N 장면별 기획안` + 아래 `*대본의 경우 AI를 사용하여 제작됩니다.`
- 13px / 줄간격 1.65 / `word-break: keep-all` + `text-wrap: balance` / 수동 `<br>` 금지 / `—` 특수문자 금지
- **편집 지시사항(자막 오버레이·전환효과·효과음 등)은 장면 설명에 넣지 않는다**
- 대표님 직접 촬영 장면은 장면 글씨 빨간색(`color:#e03030; font-weight:700`), 대표님 등장 최소화
- 헤더 배경 #1a1a1a 흰 글씨, 장면 컬럼 배경 #f2f2f2, 셀 패딩 12px 16px, 다크모드 대응
- **인쇄 PDF 대응 CSS 필수** (브라우저 인쇄 시 배경색 유지):
  ```css
  * { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
  @media print {
    :root { /* 라이트 팔레트 토큰 강제 (다크모드에서 인쇄해도 흰 배경·회색 장면 컬럼) */ }
    body { padding: 0; }
    tr { break-inside: avoid; }
  }
  ```

기획안 제시 후 **사용자 컨펌을 받고 나서** 3단계로 진행한다. 수정 요청이 오면 반영 후 다시 컨펌.

## 3단계: 촬영가이드라인 (노션 페이지)

`feedback-shooting-guide-rules.md` 메모리의 규칙을 전부 적용한다. 핵심 요약:

- 노션 MCP로 페이지 생성 (펫타임즈 스타일). 발행 위치는 사용자에게 확인
- 상단 callout: 준비물 + 촬영 개요 / 컷별 callout으로 **한 호흡(한 문장·한 컷)씩** 장면 가이드
- **편집 지시 절대 금지** (자막·전환·효과음·슬로우모션 언급 X)
- 촬영자 시점 정보만: 각도·구도 / 소품·배경·상황 / 강조 포인트 / 주의사항 (예: "손만 클로즈업")
- 레퍼런스 이미지는 사용자가 직접 삽입 → 노션에 이미지 넣지 않음
- 대표님이 직접 해야 하는 촬영은 명확히 표시, 촬영 편의성 최우선
